| 项 | 值 |
|---|---|
| 版本 | v1.0（2026-10-23） |
| 状态 | 已实现并通过真实模型验证 |
| 核心诉求 | 准确率 × 成本 双维度评测 |
| 关联文档 | [README.md](../README.md)（使用手册） |

## 问题背景（Problem Statement）

业务需要用多模态大模型对图片做**场景检查**（如"图中有自行车吗"+"收银台干净吗"），在上线前必须回答两个问题：

1. **哪个模型在我自己的数据上最准？** 公开榜单分数与自有业务场景表现经常脱节，必须用自有图片+人工标注实测；且"准确率"不能只有一个总分——需要知道**哪个检查项是弱项**、错题是"模型真错"还是"标准歧义"。
2. **这个模型用起来多少钱？** 生产按调用量付费，选型时必须知道单次调用成本、每千次调用成本，与准确率放在一起权衡；推理型模型的思考 token、按图多检查项的调用次数折算，拍脑袋估不准。

此外评测过程本身有工程痛点：多家 API + 本地模型接入方式不一、标注数据格式不统一、大批量跑测中断后重跑浪费钱、模型不按格式回答导致误判。

## 方案（Solution）

一套可复用的命令行评测流水线（`python3 -m vlmeter run`）：自有图片+标准答案整理成 JSONL/CSV，一条命令并发调用多个多模态模型（API 商用 + 本地开源），自动判分并生成 Markdown 对比报告：

- **三类任务**：`checklist`（一图多项是/否场景检查，单次调用返回全部判定+依据，主打场景）、`classification`（选项分类/打标）、`vqa`（开放问答，四种判分策略）
- **准确率多层呈现**：总体/分任务/分检查项/分类目准确率 + 错题样本（含模型判定依据 reason）
- **成本实测核算**：按模型单价 × 实际输入/输出 token 用量估算，输出本次总成本、单次调用成本、每千次调用外推成本
- **工程可靠性**：断点续跑（按判定点缓存）、失败自动重试、推理模型空响应重试、格式解析鲁棒（枚举选项/加粗/JSON 包裹均能解）、图片自动压缩、数据集校验
- **可扩展**：加模型只改 `config/models.yaml`，不改代码；离线 mock 模型零成本自测

## 用户故事（User Stories）

**评测执行**
1. 作为评测负责人，我想一条命令同时跑多个模型对比，这样不用为每家模型写一遍调用代码。
2. 作为评测负责人，我想先用 `--limit 20` 小规模试跑验证数据和配置，确认无误再全量跑，避免浪费 API 费用。
3. 作为评测负责人，我想评测中断后重跑只补失败和缺失的题，这样断网/限流不产生重复费用。
4. 作为评测负责人，我想换数据集后结果自动按内容指纹隔离，这样不同批次的数据不会互相污染缓存。
5. 作为评测负责人，我想随时用 `report` 命令基于已有结果重新出报告，这样调整报告口径不用重跑评测。
6. 作为评测负责人，我想并发调用并按模型独立限流，这样既快又不触发服务商限流。

**场景检查（核心场景）**
7. 作为业务方，我想一张图配多个是/否检查项（有自行车+收银台干净），一次模型调用全部判定，这样评测成本和线上推理成本一致且最省。
8. 作为业务方，我想给主观检查项写判定标准（criteria）只进提示词，报告里仍用短名，这样模型和标注员对"干净"的理解对齐。
9. 作为业务方，我想每个检查项返回模型判定依据（reason）并落盘，这样看到判错时能立刻分辨是模型能力问题还是标准歧义。
10. 作为业务方，我想报告按检查项分列准确率，这样一眼定位"收银台整洁 71%"这类弱项场景。

**准确率可信**
11. 作为算法工程师，我想模型枚举选项后给结论时（"A 不符，答案是B"）解析器取结论而不是第一个字母，这样格式不守规不被误判为错。
12. 作为算法工程师，我想分类题模型用自由文字描述答案时由 LLM 裁判映射回选项，这样测的是视觉能力而不是指令遵循。
13. 作为算法工程师，我想开放问答可选 exact/contains/numeric/judge 四种判分，这样计数题、编号题、语义题各有合适的口径。
14. 作为算法工程师，我想数值判分支持中文数字（"三个"），这样中文回答不因格式被判错。
15. 作为算法工程师，我想请求失败和未判定不计入准确率分母，这样网络问题不会被算成模型答错。
16. 作为算法工程师，我想推理模型思考耗尽 token 返回空答案时自动重试，这样偶发空响应不污染结果。

**成本核算**
17. 作为成本负责人，我想按官网单价配置模型价格，用实际 token 用量算钱，这样成本是实测的不是估的。
18. 作为成本负责人，我想报告给出每千次调用成本，这样直接外推生产预算。
19. 作为成本负责人，我想 checklist 一图多项按一次调用计费（自动去重），这样成本不被多检查项虚增。
20. 作为成本负责人，我想本地模型 API 成本计 0 并与 API 模型同表对比，这样"上 GPU 自建"和"买 API"能放在一张表里权衡。

**数据与接入**
21. 作为标注员，我想用 JSONL 或 CSV 整理图片+问题+标准答案，数据格式错误时逐行报清楚原因，这样不用写代码也能准备数据集。
22. 作为标注员，我想超大图片自动压缩到 API 友好尺寸，这样不用预先处理图片。
23. 作为算法工程师，我想加模型只需在 yaml 注册（提供商/模型ID/密钥环境变量/单价），不改代码。
24. 作为算法工程师，我想本地 vLLM/Ollama 模型与 API 模型跑同一套题同表对比。
25. 作为运维，我想密钥从环境变量或 .env 读取不进代码库，代理环境下官方 OpenAI 端点可显式指定避免密钥发错服务端。
26. 作为开发者，我想用离线 mock 模型零成本验证整条流水线（含报告和续跑），这样改代码后有可靠的回归手段。

## 实现决策（Implementation Decisions）

- **模型接入**：OpenAI 兼容接口作为主干适配器（覆盖 OpenAI/DeepSeek/GLM/Qwen/硅基流动/vLLM/sglang/LM Studio），Anthropic、Gemini、Ollama 各一个轻量适配器，统一走 httpx/官方 SDK；全部实现同一异步接口 `chat(image_path | None, prompt)`，纯文本调用（judge 路径）传 `None` 即可
- **任务模型**：数据集一行 = 一个评测单元；`checklist` 单元在运行时展开为多个判定点记录（`图ID::检查项名`），统计与缓存均以判定点为粒度
- **checklist 契约**：提示词要求返回 `{"1": {"verdict": "是", "reason": "依据"}}`；解析器对旧格式纯"是/否"、布尔、`["是", "依据"]` 数组、markdown 代码块包裹均兼容；漏答/非法值按答错计并标注 `parse_fail`
- **打分分层**：确定式判分优先（选项匹配/精确/包含/数值），LLM 裁判仅兜底两类——开放问答语义判分（judge 只收文本不看图，任意纯文本模型可担任）、分类题自由回答映射回选项；分类解析优先级为 答案短语 > 加粗字母 > 末尾字母 > 选项文本包含（对抗模型枚举选项）
- **缓存与续跑**：结果为 append-only JSONL，路径 = `results/<模型>/<数据集>__<指纹8位>.jsonl`；续跑时清掉历史失败/未判定行防重复统计；判定点齐全的单元跳过
- **重试策略**：网络/限流/空响应统一指数退避重试 3 次；温度固定 0 保证可复现
- **成本模型**：适配器从各 API 响应抓取输入/输出分项 token；单价（元/百万 tokens）配在模型注册表；成本按调用去重求和（checklist 多记录共享一次调用）；未配单价显示"未配置单价"而非报错；judge 费用明确不计入被测模型成本
- **图像处理**：超过 4MB 或最长边超 1568px 自动缩放重编码，避免各提供商体积限制
- **报告**：Markdown 单文件，四个章节——总览（分任务准确率）、成本与性能（选型权衡表）、分类目/分检查项准确率、错误样本（含模型依据）

## 测试决策（Testing Decisions）

只测外部行为（输入数据 → 判定/报告），不测内部实现细节。四层接缝，自下而上：

1. **判分纯函数单测**（`tests/test_scoring.py`）：选项解析（含枚举/加粗/答案短语对抗样例）、中文数字、checklist JSON 各变体、判分模式、成本估算——无网络、毫秒级，是改判分逻辑的第一道回归
2. **适配器契约测试**（`tests/test_adapters.py`）：本地起一个 canned HTTP 服务，验证 Anthropic/Gemini/Ollama 适配器的请求体结构（图片 base64 编码位置、mime、纯文本调用无图块）与响应解析——不需要真实密钥和 GPU
3. **mock 模型端到端**（`run --models mock`）：确定性伪随机回答驱动完整链路（数据校验→并发执行→缓存→续跑→报告聚合），改 runner/report 后的零成本回归
4. **真实模型冒烟**：小规模真实 API 调用验证提供商行为差异（推理模型空响应、token 计量），一次性人工触发，不进自动化回归

已有先例：本 PRD 对应的全部功能均已按此四层验证；判分对抗样例（"A 为圆形，B 为方形。答案是B"）直接来自真实模型输出。

## 范围外（Out of Scope）

- 公开标准榜单（MMMU/MMBench/DocVQA 等）跑分与官方分数对齐——本工具只解决"自有数据上的准确率"
- 模型训练/微调/蒸馏
- GPU 利用率、电费、部署运维成本核算（本地模型只计 API 成本 0）
- 分布式/多机执行（当前 asyncio 单机并发已覆盖千级图片规模）
- 标注工具/标注平台对接（假设标注结果已具备）
- Web 界面/可视化看板（Markdown 报告为交付物）
- Prompt 自动优化、自动改写检查项
- prompt caching、批量计价等成本优化策略的精确建模

## 补充说明（Further Notes）

- **已知边界**：Ollama 适配器经契约测试验证但未在真实实例跑过（本机无 GPU）；vLLM 路径与已实测的 OpenAI 兼容适配器同代码；judge 裁判自身有判错概率，关键结论建议抽查错误样本；注册表内置单价为示例价，使用前必须按官网核对
- **单价时效**：各提供商价格变动频繁，成本数字的准确性完全取决于 models.yaml 里的配置，报告表头已提醒核对
- **指纹边界**：数据集指纹基于 JSONL/CSV 文件内容，同名图片文件内容变化不触发重跑，需 `--fresh` 强制
- **后续候选方向**（未排期）：按错误聚类自动建议 criteria 补充；报告增加准确率-成本散点图；多轮对话/视频模态支持
